# Multi-language READMEs (i18n)

contextray's README is **language-selectable on GitHub** via a language switcher at the
top of every README file:

> 🌍 **Language**: 🇺🇸 English · 🇨🇳 简体中文 · ...

## How it works (important GitHub constraint)

- GitHub renders **only the root `README.md`** on the repository homepage — there is
  no native language switching.
- Every other language lives in a **sibling file** (`README.zh-CN.md`) and is reached
  through the switcher links at the top of each file.
- `README.md` intentionally stays **English** so the repo landing page is the full
  marketing pitch, not just a list of flags.

## File naming convention

| Language | File |
|---|---|
| English (default, required) | `README.md` |
| 简体中文 | `README.zh-CN.md` |
| 日本語 | `README.ja.md` |
| 한국어 | `README.ko-KR.md` |
| Español | `README.es.md` |
| Deutsch | `README.de.md` |
| Français | `README.fr.md` |
| Português | `README.pt-BR.md` |

Use the ISO 639-1 code, with a region suffix only when needed (`zh-CN`, `ko-KR`, `pt-BR`).

## Add a new language (contributor guide)

1. Copy the current `README.md` to `README.<lang>.md`.
2. Translate the **prose content**: headings, pitch, tables, FAQ, captions.
3. **Do NOT translate**: code blocks, commands (`npx contextray scan`), the terminal
   output sample, badges, URLs, or the language switcher itself.
4. Add your language to the switcher in **every** existing README file, with your
   entry linking to your new file and the `➕` link pointing at this guide.
   Example for the English file:

   ```markdown
   🌍 **Language**: [🇺🇸 English](README.md) · [🇨🇳 简体中文](README.zh-CN.md) · [🇯🇵 日本語](README.ja.md) · [➕ help translate](docs/i18n.md)
   ```

5. In your file, highlight your own language (e.g. remove the link, keep the flag)
   so readers know where they are.
6. Open a PR — a screenshot of your translated README rendering on GitHub is
   appreciated but not required.

## Quality bar

- Keep the terminology consistent with the English version:
  `waste score` · `tool output` · `repeated reads` · `config audit` · `context carbon footprint`.
- Do not invent new sections; a translation should stay a translation. New ideas
  belong in the English README first, then get translated.
- Flag emojis (🇺🇸 🇨🇳 ...) are fine on GitHub; on some platforms they render as
  two-letter codes — that is expected and acceptable.
